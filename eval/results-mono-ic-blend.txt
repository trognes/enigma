# Fusing mono with IC as the pre-pass statistic: PASSES ITS GATE.
#
# eval/coincidence_order_probe.py --lengths 40,60,100 --keys 250
#   (and again with --seed 77 as a held-out check)
#
# ENHANCEMENTS 2a experiment E.  Same probe and same metric as the Sum f^3
# gate (results-coincidence-order.txt), which the third moment FAILED: the
# AUC of "ranks a board with c+1 correct plugs above one with c", 6000 draws
# per cell, n = 1..4 plugs, authentic telegraphic German.
#
# WHY A BLEND AT ALL.  -f already fuses IC into the n-gram target and gained
# +3.0-4.4pp across three corpora.  mono and IC are both functions of the SAME
# 26-bin histogram, so the fusion costs nothing: one decode pass, then 26
# multiply-adds for each part.  But they read that histogram differently --
# IC is invariant under relabeling the output letters, mono is not -- so one
# sees only the core-input channel of a plug toggle and the other sees both.
#
# lambda is swept in units of each statistic's own spread,
#     r = lambda * sd(ic) / sd(mono),
# so "r = 1" means IC contributes one standard deviation for every one of
# mono's.  A raw lambda is not comparable across lengths; see below.
#
# ============================================================================
# THE RESULT: THE BLEND BEATS BOTH COMPONENTS AT EVERY LENGTH
# ============================================================================
#
#            L = 40         L = 60         L = 100
#     r     seed1 seed77   seed1 seed77   seed1 seed77
#   0.00    .563  .566     .572  .576     .591  .592     <- pure mono
#   0.25    .568  .571     .581  .584     .606  .606
#   0.50    .571  .572     .586  .588     .615  .614
#   1.00    .569  .569     .587  .588     .622  .619
#   2.00    .563  .562     .582  .583     .618  .616
#   4.00    .555  .554     .574  .575     .609  .608
#   8.00    .550  .549     .568  .570     .602  .602
#   pure ic .543  .542     .561  .563     .593  .594
#
#   best gain over the better pure statistic:
#            +.007 +.006    +.016 +.012    +.029 +.025
#
# HELD OUT, NOT FITTED.  r was chosen on seed 1 and the seed-77 column is a
# disjoint draw of keys, boards and plaintexts: same optimum, same shape, same
# magnitudes within .004.  That check matters because a sweep that reports its
# own best cell is otherwise selecting on noise.
#
# THE GAIN GROWS WITH LENGTH: +.006/.007, +.012/.016, +.025/.029.  And the
# plateau is broad -- every r from 0.25 to 2.0 beats both pure statistics at
# L >= 60 -- so this is not a knife-edge tuning.
#
# THE STRIKING CELL IS L = 100.  There pure mono (.591) and pure IC (.593) are
# within .002 of each other, i.e. individually interchangeable -- and fusing
# them gains +.029.  Two statistics of equal strength combining to something
# clearly better is the signature of genuine complementarity rather than one
# of them simply being sharper, and it is what the relabel-invariance argument
# predicts.
#
# For scale: the entire mono-versus-IC question spans .010-.020 of AUC and is
# worth ~2pp end to end.  The blend's +.029 at L = 100 is larger than that gap
# anywhere.
#
# ============================================================================
# EXTENDED TO L = 167, THE OPERATIONAL LENGTH -- THE BLEND STILL WINS
# ============================================================================
#
# The sweep above stopped at L = 100, leaving the cell that matters most
# unprobed and, because of the lambda drift below, the riskiest.  Added:
#
#     L      sd ratio   pure mono   pure IC   best blend   peak r   gain
#    40         7.4       .563       .543       .571        0.5     +.007
#    60         8.8       .572       .561       .587        1.0     +.015
#   100        11.0       .591       .593       .622        1.0     +.029
#   167        14.2       .601       .625       .645       1.0-2.0  +.020
#
# ("gain" is over the BETTER of the two components at that length.)
#
# THE BLEND BEATS BOTH COMPONENTS AT ALL FOUR LENGTHS, and keeps its
# over-plugging advantage at 167 too: at four wrong plugs it reads .407 against
# IC's .432 and mono's .433, still the most resistant of the three.
#
# AND THE DOCUMENTED mono/IC CROSSOVER IS NOW A CLEAN FOUR-POINT CURVE -- mono
# ahead at 40 and 60, tied at 100, IC clearly ahead at 167.  That is the third
# independent reproduction of it, from a measurement that never runs a climb.
#
# ============================================================================
# THE IMPLEMENTATION QUESTION: lambda IS NOT LENGTH-INVARIANT
# ============================================================================
#
# The binary would need a raw lambda, and raw lambda = r * sd(mono)/sd(ic).
# That ratio is measured at 7.4 / 8.8 / 11.0 for L = 40 / 60 / 100 -- close to
# the sqrt(L) that theory predicts, since IC is a rate over C(L,2) pairs (sd
# ~ 1/L) while mono is a mean of L terms (sd ~ 1/sqrt(L)).  Dividing out:
# 1.17 / 1.14 / 1.10 times sqrt(L), so slightly sub-sqrt.
#
# So the optimal RAW lambda rises steeply with length.  The L = 167 cell
# SETTLES the design, and rules out the fixed constant an earlier version of
# this file offered as the simplest option:
#
#              r that each rule gives, against the measured peak r
#     L        peak r     lambda = 0.1*L     fixed lambda = 6.5
#    40         0.5           0.54                 0.88
#    60         1.0           0.68                 0.74
#   100         1.0           0.91                 0.59
#   167       1.0-2.0         1.18                 0.46
#
# A LENGTH-PROPORTIONAL lambda tracks the peak at every length; a fixed lambda
# drifts AWAY from it, because the two effects compound rather than cancel --
# a fixed lambda makes r fall with length while the measured peak r rises.  At
# L = 167 the fixed rule sits at r = 0.46 against a peak of 1-2, i.e. wrong at
# exactly the length that matters.  With only L <= 100 probed the two rules
# looked comparable; they are not.
#
# RECOMMENDED: lambda = 0.1 * textlength.  The binary knows the length, so it
# is no harder than a baked constant.
#
# ============================================================================
# THE TWO GAPS THIS RESULT OPENED WITH ARE NOW CLOSED
# ============================================================================
#
# THE OVER-PLUGGING QUESTION IS NOW MEASURED, AND IT GOES THE RIGHT WAY.  The
# worry was that a blend might inherit IC's weaker resistance to spurious
# plugs and lose more to over-plugging than its AUC gain returns.  It does the
# opposite -- AUC of n WRONG plugs against the empty board, where LOWER means
# more resistant:
#
#   wrong      L = 40              L = 60              L = 100
#   plugs   ic  mono  blend     ic  mono  blend     ic  mono  blend
#     1   .493 .490  .490     .492 .487  .484     .487 .486  .480
#     2   .479 .478  .477     .479 .464  .459     .468 .474  .458
#     3   .478 .465  .465     .475 .451  .446     .459 .464  .446
#     4   .461 .456  .448     .464 .435  .427     .451 .453  .432
#
# (blend at r = 1.0.)  At or BELOW both components in every cell, with the
# margin widening as junk accumulates.  L = 100 shows the complementarity
# signature a second time: ic .451 and mono .453 are tied and the blend
# reaches .432.  So the blend both finds correct plugs better AND rejects
# wrong ones better; there is no trade to price.
#
# AND THE GAIN IS PRESENT AT EVERY c, not concentrated at one plug count:
#
#   -> c      L = 40              L = 60              L = 100
#          ic  mono  blend     ic  mono  blend     ic  mono  blend
#     1   .528 .541  .546     .545 .551  .565     .569 .565  .593
#     2   .543 .566  .573     .564 .567  .587     .597 .593  .627
#     3   .561 .585  .596     .578 .597  .612     .611 .616  .647
#     4   .568 .600  .609     .585 .618  .631     .637 .637  .671
#
# Gain over the better component: +.005..+.011 (L=40), +.013..+.020 (L=60),
# +.024..+.034 (L=100).  Twelve cells of twelve.  At L = 100 it grows with c
# as well as with length, so the blend helps most exactly where the pre-pass
# is doing its most useful work.
#
# r = 0.5 edges r = 1.0 at L = 40 and r = 1.0 edges r = 0.5 at L = 100, which
# is the same peak-r-rises-with-length drift the sweep showed.
#
# ============================================================================
# WHAT THIS DOES AND DOES NOT ESTABLISH
# ============================================================================
#
# ESTABLISHED: at the pre-pass's own job -- ordering boards by correct-plug
# count, c <= 4 -- mono + lambda*IC beats both mono and IC at three lengths on
# two independent samples, by a margin larger than the mono/IC gap itself; at
# every c separately; and it resists spurious plugs better than either, so the
# gain is not bought against over-plugging.
#
# NOT ESTABLISHED: any end-to-end number.  This probe never runs a climb, a
# restart or a recovery.  The AUC-to-recovery conversion is unknown; the only
# calibration point is that the mono/IC gap of .010-.020 here corresponds to
# ~2pp end to end, and extrapolating from one point is not a measurement.
#
# THE FALSIFICATION CONDITION FOR E IS UNCHANGED and still has to be met:
# build the token, then measure once at L = 60 and L = 167, and if the blend
# fails to beat BOTH m4f10 and i4f10 at BOTH lengths, drop it rather than
# re-tuning lambda.  Note L = 167 is outside the range probed here, and the
# lambda drift above is exactly why that cell is the risky one.

# ---------------------------------------------------------------------------

# It wins the other three, and wins both arms at an added L = 100.  The token
# was adopted anyway as a judgment call, with lambda NOT re-tuned.
#
