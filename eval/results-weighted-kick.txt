# A WEIGHTED KICK IS A LARGE WIN AT LOW RESTART COUNTS AND IS SUBSUMED BY
# RESTARTS ABOVE R = 6.  In the SHIPPED configuration at 3200 keys it is worth
# +29.5% of breaks at R = 1 (z = +3.79), +25.2% at R = 2 (pooled z = +5.57 over
# two seeds), +8.8% at R = 4 (pooled z = +2.65), and nothing at R = 8
# (z = -0.34).  It is also ~5% CHEAPER at every R, so these are wins on both
# axes rather than trades.
#
# THE R SWEEP CAME LAST AND IT SHOULD HAVE COME FIRST.  Every table below the
# next section was run at R = 8, which is past the crossover, so they measure
# the regime where the lever is already dead and describe it as dead
# everywhere.  Read the R sweep first; the rest is the anatomy of why it fades.
#
#   objs=$(ls src/[a-z]*.o | grep -vE 'main.o|enigma.o')
#   g++ -std=c++17 -O3 -pthread -Isrc -o /tmp/wkick eval/proto_wkick.cc $objs
#   /tmp/wkick [keys] [restarts] [L] [temperature] [kick] [-M] [cap] [seed]
#     cap = 0 skips the cap climb -- both an ablation and a real arm
#
#   eval/proto_plugrank.cc measures the mechanism this rests on.
#
# ============================================================================
# THE IDEA
# ============================================================================
#
# The kick that starts every restart draws its plug pairs UNIFORMLY.  But all
# 325 single-plug boards can be scored under IC in ~15 us per key on the T
# representation (eval/results-tseed-proto.txt), so the kick could instead draw
# with probability exp(z / T) over those scores -- a softmax on the z-score of
# each plug's own IC.  T -> infinity is the uniform kick, T -> 0 is the greedy
# argmax, and everything between is a continuous dial.
#
# THE MOTIVATION WAS A SPECIFIC DIAGNOSIS.  eval/results-beam-seeds.txt found a
# beam over the same scores losing at every budget past ~8 seeds, and blamed
# SHARED ANCESTRY: a width-W beam's leaves hang off common prefixes, so its
# seeds sit 6.1 apart against the kick's 17.4, and diversity collapses rather
# than degrading.  A weighted kick has NO ancestry -- every seed is an
# independent draw -- so it was the clean test of that diagnosis.
#
# ============================================================================
# THE PRECONDITION HOLDS: TRUE PLUGS ARE ENRICHED AT THE TOP
# ============================================================================
#
# L = 100, 100 keys, 10-pair board hidden, rotor key given:
#
#   mean rank of a true plug        109.9 of 325     (chance 163.0)
#   true plugs in the top 10         12.1%           (chance  3.1%)   3.9x
#   true plugs in the top 25         23.6%           (chance  7.7%)   3.1x
#   true plugs in the top 50         37.9%           (chance 15.4%)   2.5x
#   true plugs in the top 100        54.1%           (chance 30.8%)   1.8x
#
# So a single plug's own IC score really does carry information about whether
# that cable is in the board.  THAT IS NOT IN TENSION with the finding that the
# joint four-plug IC argmax is wrong (eval/results-seed-landscape.txt): the
# MARGINAL signal is what is being sampled, and sampling is precisely what
# avoids committing to the bad joint argmax.
#
# And the sampler delivers what the enrichment predicts.  Expected true plugs
# in a 4-plug kick, before any climbing:
#
#   weighting       true plugs / 4    vs uniform    apart
#   uniform             0.124            1.00x      13.44
#   softmax T=4         0.145            1.17x      13.41
#   softmax T=2         0.175            1.41x      13.29
#   softmax T=1         0.263            2.11x      12.72
#   softmax T=0.5       0.441            3.55x      10.34
#   softmax T=0.25      0.583            4.70x       6.42
#
# ============================================================================
# THE RESTART COUNT IS THE VARIABLE THAT MATTERS
# ============================================================================
#
# Shipped configuration (kick 10, cap-4 climb under k, f10 continuation),
# T = 1, 3200 keys per cell, paired:
#
#   R    uniform   weighted   onlyA/onlyB      z      effect   ms/key A -> B
#   1      261       338        168/245     +3.79    +29.5%    0.52 -> 0.50
#   2      393       492        182/281     +4.60    +25.2%    1.02 -> 0.98
#   3      599       677        289/367     +3.05    +13.0%
#   4      682       742        291/351     +2.37     +8.8%    2.03 -> 1.94
#   5      773       844        292/363     +2.77     +9.2%
#   6      893       903        337/347     +0.38     +1.1%
#   8     1052      1043        346/337     -0.34     -0.9%    4.11 -> 3.88
#
#   second seed at R = 2 and R = 4: 420 -> 497 (z = +3.33) and 707 -> 741
#   (z = +1.37), so pooled z = +5.57 and +2.65.  Same sign, smaller -- the
#   first seed was the larger, as usual.
#
# THE CORRECTNESS ADVANTAGE IS CONSTANT; THE BREAK ADVANTAGE IS NOT.  The
# weighted seeds hold ~18% correct plugs against ~15% at BOTH R = 1 and R = 8
# (1.23 of 6.85 against 1.00 of 6.69, and 1.20 of 6.85 against 0.96 of 6.70).
# So the lever delivers the same seed improvement at every budget, and only its
# CONVERSION decays.  What changes is what the alternative supplies: at R = 1
# there is no diversity to be had, so a better seed is the only thing available;
# by R = 8 the restarts have supplied it and the bias is buying something
# already in hand.
#
# THAT IS THE SAME SHAPE --polish HAS, which CLAUDE.md records as a lift that
# "roughly halves R80 -> R160 and can vanish by R160".  A low-budget improvement
# subsumed by restarts is a recurring pattern here rather than a property of
# this lever.
#
# AND R = 4 IS OPERATIONAL, not academic.  CLAUDE.md's unknown-key budget
# analysis puts the affordable restart count on a real full-keyspace sweep at
# roughly 4 to 12 -- so the crossover sits inside the range a genuine attempt
# runs at, and the +8.8% at R = 4 is in the part of it that a 24-hour exact
# sweep can afford.
#
# ============================================================================
# AT R = 8 IT IS A NULL, AND THE REST OF THIS FILE IS THAT REGIME
# ============================================================================
#
# Arm A is perturb_steckerbrett(), the shipped uniform kick; arm B draws the
# same number of pairs from the softmax.  EVERYTHING DOWNSTREAM IS IDENTICAL --
# the same cap-4 climb under k makes the seed, the same hillclimb<false> at cap
# 10 under -f is the continuation, the same keys in the same order.  400 keys,
# R = 8, L = 100, kick 10, no -M.  Arm A is constant across the rows by
# construction:
#
#   T        A brk   B brk   B true/seed   B apart   onlyA/B      z
#   0 (ctrl)   128     127      0.94        17.28     42/41     -0.11
#   4          128     105      0.98        16.63     50/27     -2.62
#   2          128     125      1.05        16.13     40/37     -0.34
#   1          128     135      1.14        15.34     44/51     +0.72
#   0.5        128     119      1.28        13.95     49/40     -0.95
#   0.25       128     105      1.33        12.34     54/31     -2.49
#
#   T = 0 IS THE CONTROL AND IT IS CLEAN: with the weights flat, arm B is arm A
#   with a different RNG stream, and it matches on every column (127 against
#   128, apart 17.28 against 17.25).  A harness that failed here would make the
#   rest unreadable.
#
# THE ONLY POSITIVE CELL DID NOT SURVIVE POWER.  T = 1 read +0.72 at 400 keys;
# at 3200 keys it is 1043 against 1052, z = -0.34, and T = 1.5 reads +0.71 --
# i.e. the sign wanders and the magnitude does not grow.  Both are nulls:
#
#   T      A brk of 3200   B brk   B true/seed   B apart   onlyA/B      z
#   1          1052         1043      1.20        15.34    346/337    -0.34
#   1.5        1052         1071      1.13        15.94    345/364    +0.71
#
# THE MECHANISM WORKED THROUGHOUT, which is what makes this a real negative
# rather than a failed implementation.  Seed true-plug count rises monotonically
# with the bias (+25% at T = 1 after the climb, +43% at T = 0.25) and apartness
# falls monotonically (-11%, -29%).  The dial did exactly what it was built to
# do; the break rate simply does not respond to it.
#
# NOR IS IT A COMPUTE ARTEFACT.  The weighted arm is slightly CHEAPER in total
# (0.92-0.97x of arm A's ms/key at every temperature) because its seeds
# converge faster, so it is not paying for the 325-plug scan out of the
# restart budget.
#
# ============================================================================
# BUT IT IS NOT A NULL EVERYWHERE -- AND WHERE IT WORKS DOES NOT HELP
# ============================================================================
#
# The rows above use the shipped kick of TEN pairs, and ten pairs occupy 20 of
# the 26 letters -- so by the last picks almost nothing is legal and the
# weighting has no room to act.  Measured, the bias is diluted at two separate
# stages before the continuation ever sees it:
#
#   true plugs in the raw 4-plug kick, T = 1     0.124 -> 0.263    +111%
#   ... in the seed after the cap-4 climb        0.43  -> 0.47     +9%
#   ... at kick 10 (dilution + climb)            0.93  -> 1.14     +23%
#
# SO THE CAP CLIMB ERASES MOST OF WHAT THE KICK PUTS IN.  It is a strong enough
# optimiser to forget where it started, which is the more interesting of the
# two erasures and is confirmed by ablating it -- handing the kicked board
# straight to the continuation with no cap climb at all (400 keys, kick 4):
#
#   T          uniform   weighted   B true/seed   B apart      z
#   0 (ctrl)      69        64         0.12        13.43     -0.61
#   1             69        71         0.25        12.74     +0.24
#   0.5           69        95         0.43        10.23     +2.91
#   0.25          69        77         0.56         6.46     +0.98
#
# With no climb the full bias survives and it converts: +38% of breaks at
# T = 0.5.  At equal R the whole arm sits far below the climbed one (95 against
# 128 for the shipped kick) -- but it is also much cheaper, so the fair test is
# matched compute, which the section "WITHOUT THE CAP CLIMB" below runs.
#
# THE UNDILUTED CONFIGURATION IS A REAL WIN, CONFIRMED.  At kick 4 with -M,
# so the seed is forced to exactly four plugs, 3200 keys:
#
#   seed          T      uniform   weighted   onlyA/onlyB      z
#   20260824     1.0       716       741       296/321      +1.01
#   20260824     0.7       716       767       265/316      +2.12
#   777          0.7       695       742       269/316      +1.94
#
#   pooled over the two independent seeds at T = 0.7: 534 only-A against 632
#   only-B, z = +2.87, effect +7.1% and +6.8% -- the same size twice.
#
# AND IT STILL DOES NOT HELP, which is what the grid says.  Sweeping kick size
# against -M at T = 0.7 (400 keys):
#
#   config              uniform   weighted      z
#   kick 10, -M off        128       121      -0.76      <- the shipped kick
#   kick 10, -M on          94       114      +2.11
#   kick  6, -M off        122       116      -0.74
#   kick  6, -M on          92       100      +0.92
#   kick  4, -M on          91       109      +2.12
#   kick  4, -M off        110       116      +0.77
#
# WEIGHTING HELPS EXACTLY WHERE -M IS ON, and -M on is itself the handicapped
# arm -- 94, 92, 91 against 128, 122, 110.  The best weighted cell in the whole
# grid is 121 and the best uniform cell is 128.  So the bias substitutes for
# plugs the climb would otherwise have had to find: it pays when the seed is
# small and forced, and adds nothing once the seed is allowed to grow.  A +7%
# improvement to a configuration 27% below the baseline is not a route to more
# breaks.
#
# ============================================================================
# WITHOUT THE CAP CLIMB IT IS A REAL CONFIGURATION -- AND STILL DOES NOT WIN
# ============================================================================
#
# The ablation above is also a proposal: if the cap climb is what erases the
# bias, DROP IT and hand the weighted kick straight to the f10 continuation.
# That makes the arm cheaper as well as biased, so it deserves a matched-
# compute test rather than the equal-R one the ablation got.
#
# IT IS PROPERLY TUNED.  T = 0.5 is an interior optimum, not an edge (400 keys,
# kick 4, R = 13):
#
#   T        1     0.7    0.5    0.35   0.25
#   breaks  104    113    125    112    101
#   true    0.25   0.32   0.43   0.51   0.56
#   apart  12.73  11.81  10.27   8.28   6.35
#
#   Note the optimum sits where neither true-plug count nor apartness is
#   extremal -- it is the trade between them that peaks, which is the clearest
#   evidence in this file that both halves matter.
#
#   READ AS BREAKS AGAINST CORRECTNESS, that row is the whole line of work in
#   one curve.  The seeds hold exactly four plugs, so the true-plug count is a
#   fraction directly:
#
#     correct plugs   6.3%   8.0%   10.8%   12.8%   14.0%
#     breaks           104    113     125     112     101
#
#   BREAKS PEAK NEAR 11% CORRECT AND FALL ON BOTH SIDES.  Below it there is too
#   little signal; above it too much diversity has been paid for the
#   correctness.  For scale: chance is 3.1%, and the IC beam -- the purest
#   four-plug board any method here produces -- sits at 17.9%
#   (eval/results-seed-landscape.txt), well past the peak, which is the
#   quantitative form of why it loses.
#
#   THE SHIPPED SEED IS NOT ON THIS CURVE AT ALL, and that is the point.  It is
#   nominally cap 4 but carries 6.7 plugs holding 0.93 true -- a lower FRACTION
#   (13.9%) than the beam and more than double the absolute count of any true
#   four-plug board here.  It wins by not respecting the cap.
#
# AND IT IS 42% CHEAPER, so it buys ~1.7x the restarts.  The two compute curves
# (400 keys, L = 100), shipped against no-climb weighted:
#
#      shipped: cap-4 climb, kick 10      no-climb weighted: T = 0.5, kick 4
#      R     breaks    ms/key             R     breaks    ms/key
#      4       85       1.97               8       95       2.34
#      8      128       4.05              13      125       4.00
#     13      171       7.04              16      123       4.78
#     16      171       8.06              20      140       6.02
#     20      194       9.90              26      137       7.80
#     26      193      12.95              32      164       9.47
#
# LEVEL AT ~4 ms AND BEATEN ABOVE IT.  At 4 ms the two are 128 against 125,
# inside the +-9.2 SE of a 400-trial cell; by ~9.5 ms it is 194 against 164,
# more than three SE apart, and the gap grows with budget.  So dropping the cap
# climb closes nearly all of the deficit the with-climb weighted arm carried --
# it is the best weighted configuration measured anywhere in this file -- and
# it does not cross.
#
# THE REASON IS THAT THE CAP CLIMB IS PRODUCTIVE WORK, NOT OVERHEAD.  It turns
# a uniform 10-plug kick into a seed holding 0.93 true plugs; the weighted
# 4-plug kick delivers 0.43.  The climb does more for the board than the bias
# does, it does it on every restart, and the 42% saved by skipping it does not
# buy enough extra restarts to make up the difference.
#
# ONE SHAPE WORTH KEEPING.  Without the climb, the UNIFORM arm collapses as the
# kick grows while the weighted arm does not (400 keys, T = 0.5):
#
#   kick        4     6     8    10
#   uniform    69    61    57    39
#   weighted   95    79    83    92
#
# More random plugs is more damage with nothing to repair it; more WEIGHTED
# plugs brings true plugs along too (0.12 -> 0.82 across that row).  So the
# bias substitutes for the climb's repair -- which is the same substitution
# seen under -M, in a setting where the climb is absent rather than
# constrained, and it is still a substitution rather than an addition.
#
# ============================================================================
# LETTING THE PRE-PASS FILL THE BOARD IS WORSE -- cap 10 AGAINST cap 4
# ============================================================================
#
# Raising the PRE-PASS cap from 4 to 10, so the k climb may keep all ten plugs
# the kick laid down rather than only blocking adds, is a different schedule
# and not a weighting question at all.  Weighting adds nothing there either
# (400 keys, R = 8, uniform baseline 127 for that configuration: T = 2 reads
# 134, T = 1 125, T = 0.5 123, T = 0.25 103), but the UNIFORM arm is worth a
# paired test on its own.
#
#   PAIRED, arm A cap 4 against arm B cap 10, uniform kick 10:
#
#     seed        cap 4   cap 10   onlyA/onlyB      z     effect
#     20260824     1052     962      436/346      -3.22   -8.6%
#     777          1024     978      418/372      -1.64   -4.5%
#     31337        1057     1023     406/372      -1.22   -3.2%
#
#     pooled 1260 only-A against 1090 only-B, z = -3.51.  All three seeds
#     negative; the seed that first showed it is the largest, which is the
#     usual regression to the mean and a reason to quote the pooled figure
#     rather than the -8.6%.
#
# THE UNPAIRED HINT POINTED THE OTHER WAY.  Two independent 400-key cells read
# 132 for cap 10 against 128 for cap 4 and looked like a small win; paired at
# the same 400 keys they read 128 against 127, and only power resolves it.
# That is the case for pairing in one example.
#
# `apart` AND `trueplg` ARE NOT COMPARABLE ACROSS BOARD SIZES, and reading them
# raw here inverts the conclusion.  At 800 keys:
#
#     pre-pass   plugs   true plugs   correct %   apart   apart/plug
#     cap 4       6.69      0.92        13.8%     17.27      1.29
#     cap 10      9.77      1.09        11.2%     21.72      1.11
#
# Cap 10 holds MORE true plugs in absolute count and a LOWER fraction, and its
# higher apartness is board size -- a 9.77-plug board has 19.5 non-fixed
# entries against 13.4, so more room to differ.  Normalised, correctness and
# diversity both fall, which is what the break count does.  Taken raw the two
# columns say cap 10 improved on both, which is the opposite of the truth.
#
# THE MECHANISM IS THE PRE-PASS TRAP CLAUDE.md ALREADY DOCUMENTS, in its cap
# rather than its model: filling the board under k means the WEAKER model
# places all ten plugs and f10 inherits its mistakes instead of doing the
# placement itself.  A cap of 4 leaves f10 the real work.  This extends the
# documented "a stage cap in 1..4 is INERT on an IC pre-pass" -- inert relative
# to each other, because below the kick size a cap only blocks adds, but a cap
# AT the kick size is a different climb and is materially worse.
#
# ============================================================================
# WHAT THIS REFUTES
# ============================================================================
#
# THE SHARED-ANCESTRY DIAGNOSIS OF THE BEAM'S FAILURE IS WRONG, or at least
# insufficient.  That diagnosis predicted a sampler with independent draws and
# graceful diversity decay would convert where the beam did not.  This is that
# sampler -- at T = 1 it holds 15.34 apartness against the beam's 6.12, well
# inside the kick's own 17.3 -- and in the shipped configuration it converts
# nothing.
#
# So it is not HOW the seeds are correlated.  A seed carrying 1.20 true plugs
# instead of 0.96 does not land the f10 continuation in a different basin often
# enough to matter, whatever the seeds' relationship to each other.  That is
# consistent with the standing result in CLAUDE.md that the hard residual is
# WRONG-BASIN failure which only a fresh restart can relocate -- and it now has
# a second, independent line of evidence: two different ways of making seeds
# better by their own score, both null-to-negative end to end.
#
# TAKEN WITH THE BEAM, THE SEED-QUALITY LINE IS CLOSED at this scale.  What is
# left unmeasured is whether the single-plug ranking is useful for something
# other than seeding -- as a move ORDER inside the climb, say, where -J already
# shows dynamic ordering is worth 2-6pp.
#
# ============================================================================
# THE SAMPLER: RENORMALISING IS UNNECESSARY
# ============================================================================
#
# Drawing from the full 325 and REDRAWING on a conflict is the same
# distribution as renormalising over the still-legal pairs after each pick --
# rejection conditions on legality, which is what renormalisation computes.
# Measured side by side, the two agree to sampling noise at every temperature,
# so the choice is pure cost:
#
#   weighting       renorm true/4   reject true/4   draws/kick   gave up
#   uniform             0.124           0.120          5.30        0.0%
#   softmax T=4         0.141           0.142          5.33        0.0%
#   softmax T=2         0.171           0.173          5.42        0.0%
#   softmax T=1         0.250           0.252          5.99        0.0%
#   softmax T=0.5       0.442           0.439         19.54        0.0%
#   softmax T=0.25      0.616           0.595        399.04       11.2%
#
# THE FLOOR OF 5.30 DRAWS IS COMBINATORICS, not weighting: after k picks,
# C(26,2) - C(26-2k,2) pairs are dead, so the four picks succeed with
# probability 1, 0.849, 0.711, 0.585.  With a prefix sum built once per key a
# draw is a binary search over 325, so a kick costs ~50 operations against
# renormalisation's 4 x 325 = 1300.
#
# IT BREAKS DOWN AT T <= 0.5, and the hazard is silent truncation rather than
# cost: at T = 0.25 the mass concentrates enough that 11% of kicks hit the
# attempt guard and return FEWER than four pairs, which changes what is being
# measured rather than how fast it runs.  proto_wkick.cc therefore falls back
# to an exact renormalised pass when rejection fails, so a cold temperature is
# slow but never short.
#
# ============================================================================
# SCOPE
# ============================================================================
#
# One length (L = 100), one corpus, R = 8.  IC only as the ranking model; the
# shipped pre-pass is k (mono + lambda*L*IC) and the same T build yields both,
# so a mono or blended ranking is cheap to try and was not.  Nothing here
# varies R, and the beam work found the seed/diversity trade to be
# budget-dependent, so a null at R = 8 does not settle R = 1000.
#
# THE GRID IS AT 400 KEYS and only the kick-4 cell was carried to 3200 and a
# second seed.  The kick-10-with--M cell reads z = +2.11 on the same 400-key
# footing and was not confirmed, so treat it as the same effect appearing
# again rather than as an independent result -- it changes nothing either way,
# since its 114 is still below the uniform baseline's 128.
