# A BEAM ON T BEATS KICKED SEEDS AT SMALL BUDGETS AND LOSES AT LARGE ONES.
# At matched wall time it breaks 107 of 400 against 65 (z = +4.5) with 1 ms per
# key, and 213 against 236 (z = -2.4) with 8 ms.  The crossover sits at about
# 4 ms per key -- eight kicked seeds.
#
#   g++ -std=c++17 -O3 -pthread -Isrc -o /tmp/beam eval/proto_beam.cc \
#       $(ls src/*.o | grep -vE 'main\.o|enigma\.o')
#   /tmp/beam [keys] [kicked W] [beam W] [L] [apart]
#
# A PROTOTYPE, not shipped code.  It links against the repo's objects, so the
# kick (perturb_steckerbrett), both climbs (hillclimb<false>) and the scorers
# are the real ones.  The arms differ ONLY in how the seeds are produced.
#
#   arm A, what ships:  W random 10-plug kicks, each climbed to cap 4 under k.
#   arm B, the proposal: a width-W beam from the EMPTY board, one plug at a
#                        time to 4, scored on the T representation
#                        (eval/results-tseed-proto.txt) so nothing is decoded.
#
# Both then hand every seed to the SAME continuation: hillclimb<false> at cap
# 10 under -f.  400 keys per cell, L=100 telegraphic German, rotor key given,
# 10-pair board hidden, a trial counted broken at >= 50% of letters.
#
# ============================================================================
# MATCHED WALL TIME
# ============================================================================
#
#   A/B seeds   A brk   B brk    A ms/key  B ms/key  onlyA/onlyB      z
#      2/3         65     107        1.20      0.94       22/64     +4.53
#      4/7        109     156        2.10      2.10       33/80     +4.42
#      8/14       180     187        4.23      4.25       56/63     +0.64
#     16/27       236     213        8.46      8.18       57/34     -2.41
#     32/54       281     261       16.91     16.71       65/45     -1.91
#
#   z is McNemar on the paired per-key outcomes; positive favours the beam.
#   The beam width is chosen so the two arms cost the same, which is why B's
#   seed count is larger -- its seeds are ~5x cheaper to produce.
#
# THE BEAM FRONT-LOADS QUALITY, WHICH IS EXACTLY THE TRADE THE RAREFACTION WORK
# PREDICTS.  With few seeds you want the best ones and the beam supplies them;
# with many you want DIVERSE ones and the beam cannot, because it optimises
# score and its candidates crowd one region.  Distinct converged boards at
# equal seed count: 21.4 for the beam against 25.9 for kicks at W = 32.
#
# ============================================================================
# AT EQUAL SEED COUNT THE BEAM IS SIMPLY WORSE, AND THE GAP WIDENS
# ============================================================================
#
#   W       kicked brk / distinct     beam brk / distinct     (200 keys)
#    4          51 /  3.83                52 /  3.43
#    8          87 /  7.30                74 /  6.45
#   16         115 / 13.84                88 / 11.68
#   32         151 / 25.87               110 / 21.43
#
# So the beam's whole advantage is COST, not seed quality: ~5x cheaper to
# produce a seed (0.25 ms against 2.01 ms for eight), and that is what buys the
# extra seeds that win the small-budget cells.  Once the budget is large enough
# for kicks to supply plenty of diverse seeds, cheapness stops mattering.
#
# ============================================================================
# DISTINCT SEEDS IS THE WRONG MEASURE.  THE BEAM WINS IT AND LOSES ANYWAY.
# ============================================================================
#
# The tables above counted distinct CONTINUATIONS and never counted the seeds
# themselves, which left the obvious question unanswered.  Counted now, at 200
# keys, W = 8 both arms:
#
#   arm       breaks   plugs   distinct seeds   mean apart   distinct finals
#   kicked      87      6.70        7.86           17.10          7.30
#   beam        74      4.00        8.00            6.20          6.45
#
# THE BEAM RETURNS MORE DISTINCT SEEDS THAN KICKS DO -- 8.00 of 8 against 7.86,
# because `beamset` rejects a duplicate outright while two kicks can climb to
# the same board (which is exactly what --seed-dedup exists to skip).  So a
# distinct-seed count says the beam is the MORE diverse arm, and it is not.
#
# `apart` is the measure that works: the mean pairwise number of the 26 board
# entries on which two seeds differ.  17.10 for kicks against 6.20 for the
# beam, i.e. kicked seeds share almost nothing while beam seeds share most of
# their plugs.  That is STRUCTURAL: a width-W beam at depth 4 has W leaves but
# they hang off shared ancestors, so the level-1 and level-2 choices are common
# to most of the beam.  Kicks have no shared ancestry at all.  "Distinct" is
# satisfied by one plug of difference; "far apart" is not, and only the second
# predicts distinct basins after the continuation.
#
# ============================================================================
# TWO CONFOUNDS CHECKED, AND NEITHER IS THE EXPLANATION
# ============================================================================
#
# THE ARMS DO NOT PRODUCE THE SAME KIND OF BOARD.  Arm A's seeds carry 6.70
# plugs, not 4 -- without -M the cap blocks only ADDS, so a 10-plug kick
# climbed under cap 4 converges still holding ~6.7 (the effect the -M entry in
# CLAUDE.md documents).  The beam builds exactly 4 from empty.  So arm A is
# what the k4f10 schedule DOES and the depth-4 beam is what it SAYS, and the
# comparison confounded seed construction with seed size.
#
# Matching the size does not rescue it (200 keys, W = 8, kicked = 87 breaks):
#
#   beam depth    4     5     6     7     8    10
#   breaks       74    77    70    65    72    68
#   mean apart  6.20  6.38  6.42  6.34  6.46  6.65
#   finals      6.45  6.00  5.59  5.28  5.03  4.66
#
# Depth 6 matches arm A's plug count and still loses 70 to 87.  APARTNESS IS
# FLAT IN DEPTH (6.2 - 6.7 throughout) while distinct finals FALL steadily,
# 6.45 -> 4.66: a deeper beam commits harder to its shared prefix, so its
# leaves converge to fewer basins.  The size confound is real and is not the
# mechanism.
#
# ============================================================================
# THE SEPARATION CONSTRAINT HELPS A LITTLE, AND ITS FIRST VERSION COULD NOT
# ============================================================================
#
# `apart` requires kept beam entries to differ in at least that many plugged
# letters.  Rejecting a near neighbour, or evicting a worse one, keeps W
# entries:
#
#   W = 16:  apart 0 -> 88 breaks,  apart 4 -> 92
#   W = 32:  apart 0 -> 110,        apart 4 -> 120
#
# AND IT HELPS EXACTLY IN PROPORTION TO THE APARTNESS IT BUYS, which is the
# check that turns the knob from a knob into evidence (200 keys, W = 16):
#
#   arm / setting     breaks    mean apart    distinct finals
#   beam apart 0        88          6.73           11.68
#   beam apart 4        92          8.26           12.20
#   kicked             115         17.20           13.84
#
# apart = 2 and 3 are INERT, byte-identical to 0: a board differing by one plug
# already differs in at least 2 entries, so nothing below 4 rejects anything
# the duplicate check does not.  apart = 4 moves apartness 6.73 -> 8.26 and
# breaks 88 -> 92, still half of the kicked arm's separation.  So the
# constraint works in the right direction and cannot reach far enough: it
# prunes within a beam whose candidates already share their ancestry.
#
# A FIRST VERSION FILTERED THE FINISHED BEAM instead, which could only SHRINK
# the seed count -- it lost breaks by returning fewer seeds and would have been
# reported as "diversity does not help".  It is a replacement rule now.
#
# apart >= 6 IS DEGENERATE, NOT INFORMATIVE.  At level 1 only two letters are
# plugged, so no two candidates can differ by six; the beam collapses to width
# 1 and returns one seed (24 breaks, 1.00 distinct).  A threshold that scales
# with the level would be the way to test stronger separation.  apart = 4 is
# the strongest setting that is reachable from level 2 onward, and it is what
# the table above uses.
#
# ============================================================================
# ONE HARNESS BUG WORTH RECORDING
# ============================================================================
#
# The first beam used a std::set<std::string> per level to de-duplicate, which
# allocated a 26-byte string for each of ~6000 candidates and made seed
# generation cost the SAME as the kicked climbs it exists to undercut -- 2.12
# against 2.20 ms.  That is an artefact of the harness, and reported as it
# stood it would have read as a property of the method ("no cheaper").  The
# kept set is at most W, so the common path is one compare against the worst
# kept; fixing it moved seed generation to 0.25 ms.  MEASURE THE THING, NOT THE
# BOOKKEEPING AROUND IT.
#
# ============================================================================
# SCOPE
# ============================================================================
#
# One length (L=100), one corpus, one machine mode, the plugboard tier with the
# rotor key GIVEN.  The beam starts from the EMPTY board every time, so it is
# deterministic per key -- it cannot be re-run for more seeds the way a kick
# can, which is the structural reason its width cannot grow indefinitely.
#
# NOT TESTED: a hybrid.  The obvious one is to take the beam's W seeds and
# then continue with kicks, which would front-load quality without capping
# diversity.  Nothing here measures it.
#
# NOT TESTED AT OTHER LENGTHS.  The T representation's speed advantage grows
# with L (2.7x at L=60, 23.6x at L=1000), so the crossover budget should move
# with length too -- at longer messages the beam's seeds are cheaper still
# relative to the continuation, which should push the crossover to the right.
